# CONN-ADGUARD-HOME-AGENT — Requirements

Governing specification: [spec.md](spec.md).

| ID | Requirement | Acceptance |
|---|---|---|
| `CONN-ADGUARD-HOME-AGENT-R001` | **Verified transport.** The connector must take TLS trust from the SDK `resolve_tls_profile` in `adguard_home_agent/auth.py` and `adguard_home_agent/api_client.py`, verify server certificates by default, carry any per-instance CA through the profile into the client trust, and never silence the insecure-request warning. Caller chain: console_script adguard-home-agent (scion_sdk.cli:serve L18) -> scion_sdk installed_connectors -> adguard_home_agent/__init__.py::connector -> adguard_home_agent/auth.py::get_client -> adguard_home_agent/api_client.py::Api (L18) -> BaseApiClient with tls_service ADGUARD resolving the SDK TLS profile. Shape: api_client.py::Api passes tls_service=TLS_SERVICE ('ADGUARD') to scion_sdk.http.support.BaseApiClient, which calls resolve_tls_profile; auth.py::get_client documents the ADGUARD_CA_BUNDLE variables and adds no verify switch. | `tests/test_tls_profile.py` must observe verification on by default, a configured CA carried into the client trust, and no call to disable warnings. Test: `tests/test_tls_profile.py::test_default_verifies`. |
| `CONN-ADGUARD-HOME-AGENT-R002` | **Governed client.** The `Api` client in `adguard_home_agent/api_client.py` must subclass the SDK `BaseApiClient` (`SCION-CENTRALIZED-CAPABILITIES-R001`, `SCION-CENTRALIZED-CAPABILITIES-R003`), send basic credentials through the SDK `BasicAuth`, and take the 429 backoff from the SDK. The package must not import `requests` or `urllib3`. Caller chain: console_script adguard-home-agent (scion_sdk.cli:serve L18) -> scion_sdk installed_connectors -> adguard_home_agent/__init__.py::connector -> adguard_home_agent/auth.py::get_client -> adguard_home_agent/api_client.py::Api (L18) -> BasicAuth and BaseApiClient._send. Shape: Api subclasses scion_sdk.http.support.BaseApiClient and builds BasicAuth(username, password) in api_client.py (L18-L30); request() calls self._send, so retry and 429 backoff come from the SDK. | `tests/test_sdk_transport.py::test_client_is_the_sdk_base_client` and `::test_rate_limit_backoff_comes_from_the_sdk` must pass. |
| `CONN-ADGUARD-HOME-AGENT-R003` | **Same behaviour.** Each API method must keep its path, body and result shape. An error status must raise `AdGuard API error: <status> - <text>`. A 204 or empty body must return a success marker. Caller chain: console_script adguard-home-agent (scion_sdk.cli:serve L18) -> scion_sdk installed_connectors -> adguard_home_agent/__init__.py::connector -> adguard_home_agent/auth.py::get_client -> adguard_home_agent/api_client.py::Api (L18).request (L40) which every API method calls. Shape: Api.request maps status >= 400 to Exception('AdGuard API error: <status> - <text>'), 204 to {'status': 'success'} and an empty body to a success marker with message Empty response; per-method paths stay in api_client.py. | `tests/test_sdk_transport.py::test_request_shapes_are_unchanged` must pass. |
| `CONN-ADGUARD-HOME-AGENT-R004` | **SDK floor.** The package must depend on `scion-sdk[mcp]` at the latest release floor and must not pin `requests` (`SCION-CENTRALIZED-CAPABILITIES-R040`). Caller chain: package install -> pyproject.toml dependencies -> scion_sdk consumed by adguard_home_agent/api_client.py and the console_script adguard-home-agent. Shape: pyproject.toml dependencies carry scion-sdk[mcp] at the release floor with no requests or urllib3 entry; no code change beyond the pin. | `tests/test_sdk_transport.py::test_dependencies_come_from_the_sdk` must pass. |
